# معماری BestWash

## مرزهای اعتماد

- Web فقط داده نمایشی و ورودی کاربر را نگه می‌دارد؛ قیمت، ظرفیت، Hold، تخفیف و نتیجه پرداخت در API محاسبه می‌شوند.
- API تنها منبع حقیقت رزرو است و ایجاد رزرو را بعد از Verify پرداخت انجام می‌دهد.
- Worker به شبکه داخلی PostgreSQL/Redis متصل است و پیامک را از Outbox قابل Retry ارسال می‌کند.
- پنل ادمین Session مستقل، 2FA، RBAC، Audit Log و Security Event دارد.

## تضمین‌های تراکنشی

- درخواست پرداخت با `Idempotency-Key` یکتا است.
- Claim پرداخت با Update شرطی انجام می‌شود و Callback تکراری رزرو دوم ایجاد نمی‌کند.
- موجودی کیف پول با شرط موجودی کافی کم و در خطای درگاه آزاد می‌شود.
- کش‌بک فقط از مبلغ واقعی درگاه، پس از تکمیل خدمت و با کلید یکتای رزرو ثبت می‌شود.
- کد تحویل Hash می‌شود؛ نسخه لازم برای نمایش/پیامک با AES-256-GCM رمز است و متن خام در Outbox ذخیره نمی‌شود.
- گذار وضعیت رزرو فقط از جدول State Machine مجاز است و تاریخچه/بازیگر ثبت می‌شود.

## منشأ رزرو

هر Booking دارای `source` است:

- `CUSTOMER_APP`: رزرو مستقیم مشتری
- `ADMIN_MANUAL`: رزرو ساخته‌شده در پنل برای مشتری

هر دو منشأ از یک مسیر ظرفیت، Checkout، پرداخت و عملیات استفاده می‌کنند و در پنل Badge مستقل دارند.
